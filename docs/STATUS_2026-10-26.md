## Temporary NGINX proxy validation

A local config file was created at the user's configuration directory and syntax-checked with a temporary NGINX container using a read-only mount. The container initially could not read the file until the file mode was changed to `644`; the containing config directory remained mode `750`. No credentials are stored in this config.

A temporary rootless container was then started with:
- `--network=pasta:-T,11434`
- host publish binding `127.0.0.1:11435:8080`
- all Linux capabilities dropped
- `no-new-privileges`
- the NGINX config mounted read-only

Observed local results through that temporary proxy:
- `GET /api/tags` returned **HTTP 200** and the expected `qwen3:8b` model listing.
- `GET /v1/models` returned **HTTP 200** and listed `qwen3:8b`.
- `POST /api/generate` with `stream:false` returned **HTTP 200** and the requested response `proxy-ok`.

This confirms the Host-header rewrite works for local discovery and a real inference request through the temporary proxy.

A streaming request to `/api/generate` also returned multiple JSON chunks incrementally through NGINX. The test ended with `done_reason:"length"` after reaching its 32-token generation limit while producing the model's thinking field, so this verifies stream transport but not a completed user-facing count response.

The persistent rootless Quadlet service was then created and started under the user's systemd manager. The persistent service returned **HTTP 200** from `/api/tags`, `/v1/models`, and a non-streaming `/api/generate` request, with expected responses. A streaming request through the earlier temporary proxy emitted multiple JSON chunks; the run hit its deliberately low token limit during the model's thinking field, so stream transport passed but that prompt did not finish normally.

The persistent service is active at the last observed checkpoint. Its Quadlet includes `Restart=on-failure`, `WantedBy=default.target`, rootless `pasta` networking, and a loopback-only publish binding. User lingering is enabled (`Linger=yes`), and the service appears under the user `default.target` dependency list. A real reboot without interactive login is still needed to verify boot behavior.

## Security notes

- Keep Tailscale Serve tailnet-only; do not enable Funnel or expose Ollama's port publicly.
- The observed tailnet access policy used a wildcard allow-all rule. This is tailnet-wide access under that policy, not a device-specific allowlist.
- The proxy plan does not hard-code an API endpoint allowlist. API paths are forwarded according to proxy configuration, so access control must be understood at the tailnet boundary.
- Never publish private tailnet URLs, hostnames, IP maps, raw packet captures, identity headers, keys, or unredacted diagnostic logs.
